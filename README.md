# 自作デスク

暮らしを便利にするための **電子工作・スマートホーム・DIY・自作PC・3Dプリント・修理** など、自作したもの（作りたいもの）をまとめて管理するアプリです。作品ごとに **仕様・部品と工具・段取り（手順と作業日）・製作と使用の記録（写真つき）・完成後のメンテナンス** を一か所に置けます。

電子部品や工具は、研究管理アプリ **[研究デスク](https://kuru77.github.io/lab-desk/)** の「部品・工具」台帳で管理し、こちらからたどれるようにしています（[研究デスクとの連携](#研究デスクとの連携)）。

**→ https://kuru77.github.io/maker-desk/**

依存ライブラリなしの `index.html` 1枚。データはブラウザの中（記録は localStorage、写真は IndexedDB）に保存されます。[同期](#端末間の同期google-アカウント)を使うと、自分の Google ドライブのアプリ専用領域にも保存されます。それ以外の外部には送信しません。オフラインでも開けます。

## 画面

| タブ | 内容 |
|---|---|
| 自作 | 作品の一覧（状態・種類で絞り込み）、2週間以内の作業日とメンテナンス、買うものの数 |
| 予定 | 全作品の作業日とメンテナンスを「過ぎている / 今週 / 今月 / それ以降」でまとめて表示。作業日が決まっていない作品も出る。**カレンダーに追加（.ics）** |
| 買い物 | 全作品の「要購入」を購入先ごとにまとめた買い物リスト（金額の目安つき・テキストでコピー）。注文済みのもの、研究デスクで補充ラインを下回っている部品も |
| 部品・工具 | 研究デスクの台帳（読むだけ）。未使用の数・保管場所と、どの作品・研究で使っているか |
| 設定 | 端末間の同期、研究デスクとの連携、テーマ、バックアップ、CSV 書き出し、サンプルデータ |

### 作品ごとのページ

| | |
|---|---|
| 概要 | 種類（電子工作 / スマートホーム / 自作PC / DIY・木工 / 3Dプリント / 修理・改造 / その他）・状態（アイデア / 段取り中 / 製作中 / 稼働中 / 保留 / 引退）・目的・設置場所・期間・タグ。**仕様・設定値**（IP アドレス、ファームウェアの版、寸法、パーツ構成など「項目：値」の表）と、段取りの状況・次の予定・最新の記録。安全上の注意・備考と、読み取った**元の資料** |
| 部品・工具 | 部品・材料と工具・道具の表。数・単価（合計を自動計算）・購入先・URL。状態ボタンをタップで **要購入 → 注文済み → 手元にある → 取り付け済み** と進む（工具は「用意できた」まで）。研究デスクの台帳の部品につなぐと在庫と保管場所が見える |
| 段取り | **準備**（買うもの・届くのを待つもの・使う工具・残りの手順と目安時間）、**作業日**（日付・時間・その日にやること）、**手順**（番号つき・目安時間・注意が要る作業の印・↑↓ で並べ替え・チェックで完了） |
| 記録 | 日付つきの製作・使用の記録。写真（その場で撮影も可）を何枚でも添えられる。最新の写真が一覧のサムネイルになる |
| メンテ | 電池交換・フィルター掃除・ファームウェア更新・ネジの点検など、周期（日）つきのくり返し作業。「やった」で記録に残り、次の日付が決まる |

- 新しく作るとき、**種類に合わせたひな形**（手順・よく使う工具・仕様の項目・メンテナンス）を入れられます。自作PC なら CPU・マザーボード・メモリなどのパーツ欄と、互換性確認 → 最小構成で起動 → 組み込み → OS → BIOS 設定 → 温度確認 の手順が入ります
- 手順を 1 つチェックすると状態が「製作中」に、すべて終わると「稼働中」にするか聞きます（完成日が入り、メンテナンスの周期はそこから数えます）

## 資料の読み取り

研究デスクと同じ仕組みで、手元の製作メモ・手順書・予定表・作業記録を読み取って自動で入力できます。ホームの **資料から追加** で新しい作品として、作品の **読み取る**（概要・段取り・記録）でその作品への追記として取り込みます。記録する前に、何がいくつ入るかを確認できます。

| 読み取れるもの | 方法 |
|---|---|
| Word（.docx） | 見出し・番号つきリスト・表をそのまま読む（通信なし） |
| PDF | 文字の大きさから見出しを判断。読み取り機能（pdf.js）は PDF を読むときだけ読み込む。画像だけの PDF は読めない |
| テキスト・Markdown・HTML・LaTeX（.tex） | 見出し（#）・箇条書き・表を読む |
| Google ドキュメント | URL を貼り付け。初回は Google のログイン画面で「閲覧のみ」の許可を求める |
| 貼り付け | ほかのアプリでコピーしたテキスト |

振り分け先と手がかり：

| 振り分け先 | 手がかり |
|---|---|
| 目的・概要 / 仕様・設定値 | 「目的」「概要」「仕様」「構成」などの見出し、「項目：値」の行、2 列の表 |
| 部品・材料 / 工具・道具 | 「部品」「材料」「買うもの」「工具」などの見出し。「×2」「3本」「¥1,200」から数と単価を読む。品名・型番・数量・単価・購入先の列がある表はそのまま部品表に。研究デスクの台帳に同じものがあれば自動でつなぐ |
| 手順 | 「手順」「作り方」「組み立て」などの見出し、「1.」「①」などの番号。「やけど」「感電」などを含む手順には注意の印 |
| 作業日（予定） | 「予定」「スケジュール」「日程」の見出しの下や、先の日付で始まる行。「10/18(土) 13:00-16:00 回路の試作」のように時間も読む |
| 記録 | 「記録」「日誌」「作業メモ」の見出しの下や、過ぎた日付で始まる行 |
| メンテナンス | 「メンテ」「点検」の見出し。「7日ごと」「1か月おき」「毎年」から周期を読む |
| 安全上の注意・備考 | 「注意」「安全」「備考」「メモ」などの見出し |

- 種類（電子工作・自作PC・DIY など）は内容から推測し、確認画面で変えられます
- 資料の中の LaTeX の記法（`$V_{CC}=5,mathrm{V}$`、`SI{3.3}{olt}`、`tabular` など）はふつうの文字に変換します（確認画面で外せます）
- 読み取った元のファイルは作品の「元の資料」に保存され、端末間でも同期されます
- Google ドキュメントを読むには、Google Cloud で **Google Docs API** を有効にし、OAuth 同意画面のデータアクセスに `https://www.googleapis.com/auth/documents.readonly` を追加しておきます（研究デスクと同じプロジェクトなので、研究デスクで設定済みならそのまま使えます）

## ダークモード・ライトモード

画面右上の 🌙 / ☀ ボタンで、ダークモードとライトモードをその場で切り替えられます（iPhone のステータスバーの色も合わせて変わります）。設定 →「テーマ」で **端末に合わせる** に戻すと、OS の設定に従います。

## 研究デスクとの連携

電子部品・工具は研究デスクの台帳にまとめ、自作デスクはそれを **読むだけ** にしています（同じ部品を 2 か所で管理しないため）。

- **作品 → 台帳**：部品表の行を台帳の部品につなぐと、「台帳：未使用 3個・引き出し A-2」のように在庫と保管場所が出ます。足りなければ赤になります
  - 部品を追加するときは、名前・型番から台帳の同じ部品を自動で選びます。「研究デスクの台帳から」で一覧から選ぶこともできます
  - 台帳にありそうなのにつながっていない部品は「照合」でまとめてつなげます
  - 「要購入」なのに台帳の在庫で足りるものは知らせが出ます（買わずに済む）
- **台帳 → 作品**：部品・工具タブで、台帳の部品ごとに「どの作品・どの研究で使っているか」が見えます。「研究デスクで開く」でその部品のページへ飛べます
- **研究デスク側**：部品の編集画面に「自作デスクで使っている作品」が出て、作品のページへ飛べます。一覧にも「自作 n件」と出ます。作品で **取り付け済み** にした部品は、研究デスクでも **使用済み** として数えられ、未使用の数が減ります（工具は参照だけで数は変えません）

台帳の読み込み元（新しいほうを使います）：

1. **同じブラウザ**で研究デスクを使っていれば自動（どちらも `kuru77.github.io` にあるので保存場所を共有できる）。別のタブで研究デスクを編集すると、すぐ反映されます
2. **Google 同期**：両方のアプリで同じ Google アカウントの同期をオンにすると、研究デスクの同期データ（`lab-desk.json`）を読みます。iPhone のホーム画面に追加したアプリはアプリごとに保存場所が分かれるので、こちらを使います
3. **バックアップ JSON**：研究デスクの「設定 → バックアップを書き出す」で作ったファイルを、設定の「研究デスクとの連携」から読み込めます

## カレンダーに追加（.ics）

予定タブ（または作品の段取り・メンテ）の **カレンダーに追加** で、これからの作業日と 120 日以内のメンテナンスを .ics にします。iPhone では共有シートから FirstSeed カレンダーなどに送れます（追加なので、もとの予定は消えません）。

- 時間を入れた作業日は時間つき、入れていないものとメンテナンスは終日の予定になります
- 送ったものには印がつき、次からは外れた状態で開くので、同じ予定が二重に入るのを防げます（日付や時間を変えたら、また送れるようになります）

## 端末間の同期（Google アカウント）

設定 →「Google でログイン」で、同じ Google アカウントでログインした端末どうしのデータ（写真も含む）が同期されます。

- 保存先は自分の Google ドライブの **アプリ専用領域**（appDataFolder）。ドライブの画面には表示されません。サーバーは使っていません
- OAuth クライアントは研究デスクと **同じ Google Cloud プロジェクト** の自作デスク専用のものなので、アプリ専用領域も研究デスクと共通です。自作デスクのファイルは `maker-desk.json` と写真の `mk-…` で、研究デスクのファイルには書き込みません（`lab-desk.json` を読むだけ）
- 作品・部品・手順・作業日・メンテ・記録を **1件ずつ** マージするので、別々の端末で編集しても、同じ項目を同時に書き換えない限り両方の変更が残ります。削除も他の端末に反映されます
- ログインの有効期限は約1時間です。切れていたら、アプリを開いたときに自動で取り直します

### OAuth クライアント

研究デスクと同じ Google Cloud プロジェクトに、自作デスク専用のクライアント（`1088975026923-hub0du9f…`）を作り、`index.html` の `GOOGLE_CLIENT_ID` に組み込んであります。クライアントの設定は次のとおりです。

- 種類：ウェブ アプリケーション
- 承認済みの JavaScript 生成元：`https://kuru77.github.io`
- 承認済みのリダイレクト URI：`https://kuru77.github.io/maker-desk/`
- スコープ：`https://www.googleapis.com/auth/drive.appdata`（研究デスクと共通の OAuth 同意画面に登録済み）

## データの持ち運び

- **設定 → バックアップを書き出す** で JSON を保存、**読み込む** で復元。写真も JSON に含まれます
- 部品表は CSV で書き出せます（全作品をまとめて。台帳の部品名と保管場所の列つき。Excel で文字化けしないよう BOM 付き UTF-8）
